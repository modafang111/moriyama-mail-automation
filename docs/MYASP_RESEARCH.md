# MyASP 調査メモ（2026-08-29、実機追記 2026-08-30）

公式マニュアルと、管理画面での下書き保存の実機確認です。セレクタは画面変更で壊れます。

## 結論（第1段階の方針）

- 第三者アプリ向けの、配信まで含む汎用REST APIは確認できなかった。
- 読者登録や下書き、テスト配信、予約配信については **MyASP MCP Connect** が公式のプログラム連携に最も近い。
- 読者削除、即時配信は MCP 非対応と明記されている。
- 第1段階の配信処理はモックにする。次段階で MCP を優先し、不足操作だけブラウザ自動操作を検討する。

## ログイン方法

出典: [MyASPへログインしようとしたらログインできませんでした](https://docs.myasp.jp/2806/)

- 契約時メール「アカウントのご用意ができました」に、**契約者ごとのログインURL**、ID（メールアドレス）、初期パスワードが記載される。
- 管理画面ログインと「MyASP 契約ポータル」は別物。ポータル情報では管理画面に入れない。
- 共通ログインページ経由では、利用中MyASPのドメイン入力が挟まる。
- 自動化する場合の認証情報は `.env` のみ。ソースコードには書かない。
- ログインURLは顧客ごとに異なるため、プログラム側で公式の単一URLを決め打ちしない。

## メルマガ読者の管理方法

出典: [はじめてのMyASP](https://docs.myasp.jp/startup_myasp/)、[画面説明：ユーザー一覧](https://docs.myasp.jp/18969/)

- 読者は「シナリオ」単位で管理する。
- シナリオ管理メニューのユーザー一覧で検索、絞り込み、一括操作を行う。
- メルマガ用途では、主に無料メルマガ／無料オファータイプのシナリオを使う想定（顧客環境のシナリオ種別は未確認）。

## 読者追加方法

出典: [機能解説：ユーザーCSV一括登録](https://docs.myasp.jp/43857/)、[画面説明：ユーザー登録（CSV一括）](https://docs.myasp.jp/20008/)、[Zapier連携](https://docs.myasp.jp/33022/)、[MCP Connect](https://docs.myasp.jp/54344/)

確認できた手段:

1. 管理画面の個別登録
2. ユーザーCSV一括登録（ファイルまたはテキスト貼り付け。事前チェック後に登録）
3. Zapier からの登録（メールアドレス等。フリー項目は制限あり）
4. MCP Connect の読者新規登録（登録経路は「個別登録」）

CSVの公式テンプレート列は、顧客から受け取るCSVとは別物として扱う。顧客CSVの解析とMyASP反映は分離する。

## 読者削除方法

出典: [読者のアドレスを一括配信解除、または、一括削除するには](https://docs.myasp.jp/120/)

- ユーザー一覧で対象を選び、「選択したユーザーを削除する」。
- 削除するとMyASP上から参照できず、基本的に復活できない。
- MCP Connect は **読者削除に対応していない**（2026-08-25時点の公式記載）。

顧客依頼の「削除」が、この削除なのか配信解除なのかは未確定。プログラムは内部的に `remove` として持ち、MyASP側の具体操作は次段階で選択する。

## 除外方法

確認できた近い機能:

- 一括配信の「配信先のユーザーの指定」で、一覧のチェックを外すとその配信だけ対象外。[画面説明：メール作成（一括配信）](https://docs.myasp.jp/18627/)
- ラベルで絞り込む / 除外する
- 「除外シナリオ」は、別シナリオ所属による検索条件であり、今回の「今回の配信からの除外」とは意味が異なる。[追加・除外・所属シナリオ](https://docs.myasp.jp/48902/)
- 配信解除はシナリオの購読停止であり、1通だけの除外ではない。[一括配信解除](https://docs.myasp.jp/120/)

「今回の配信からの除外」をラベルにするか、配信作成時のチェック外しにするかは未確定。

## メール作成方法

出典: [画面説明：メール作成（一括配信）](https://docs.myasp.jp/18627/)、[MCP Connect](https://docs.myasp.jp/54344/)

管理画面:

1. シナリオ管理メニュー → メール作成（一括配信）
2. 配信先ユーザーを指定
3. 件名、本文、テキスト/HTML、テスト送信、配信スケジュールを入力
4. 下書き保存、または「確認する」

MCP Connect:

- 一括配信メールの下書き作成・更新
- 絞り込み配信設定の更新（指定できない項目あり）
- 配信対象0件の下書きは管理画面から開けない場合がある

## テスト送信方法

出典: [テストメールを送る方法](https://docs.myasp.jp/18615/)、[MCP Connect](https://docs.myasp.jp/54344/)

1. メール作成画面下部の「テストメール送信」にアドレスを入れて送る。置き換え文字はテスト用表記になり、添付は送られない。
2. テストユーザーを登録し、配信先をそのアドレスだけに絞り込んで一括配信する（誤配信注意）。
3. MCP の「一括配信メールをテスト配信する」。**実行にはユーザー確認が必要**。

本プログラムのテスト配信は、本番読者へ送らず、設定済み確認用アドレスのみを対象にする。

## 本番配信方法

出典: [画面説明：メール作成（一括配信）](https://docs.myasp.jp/18627/)

- 確認画面のあと、即時配信なら「配信する」。
- MCP の本番相当は **指定日時の配信予約のみ。即時配信には対応していない**。予約実行にもユーザー確認が必要。

次段階で即時配信が必要なら、MCPだけでは足りない。ブラウザ操作または「1分後予約」などの運用を、実機確認してから決める。

## 配信予約方法

- 管理画面の配信スケジュールで日時指定 → 確認 → 「配信を予約する」。
- MCP も指定日時の予約に対応（即時は非対応）。予約取消しあり。

## 公式に近い連携手段の比較

| 手段 | できること | 今回の配信業務への適合 |
| --- | --- | --- |
| 汎用REST API | 確認できず | 存在前提で実装しない |
| Zapier | 読者の登録・通知が中心 | 一括配信の作成・実行には不足 |
| 外部システムへの連動登録 | MyASP → 外部へのPOST | 逆方向の配信実行には使えない |
| MCP Connect | 読者登録、状態変更、下書き、テスト、予約 | 有力。削除と即時配信は非対応 |
| 管理画面 + ブラウザ自動操作 | 画面上のほぼ全操作 | セレクタ変更リスクあり。不足分の候補 |
| CSV一括登録画面 | 大量追加 | 顧客CSV書式が決まってから |

## 実機確認：下書き保存（2026-08-30）

ログインURLは契約者ごと。認証情報は `.env` のみ。

確認した画面:

1. `https://…/Member/` → `#SellerLoginid` / `#SellerPassword` / 「ログイン」
2. シナリオ一覧 `/member/item`。テスト用シナリオ名は「テスト」（ID `fM6ticMg`）
3. 配信先指定 `/member/userlist/{id}/item_id:{id}`
4. 「以下のアドレスに配信するメールを作成」
5. 作成画面 `/Member/add_mail`。件名 `#MailSubject`、本文 `input[name="data[Mail][body]"]`（表示は iframe エディタ）、下書きは `#MailAddMailForm` の `Submit[draft_save]`
6. `Submit[mail_save]`（確認画面へ）は押さない。配信しない。

注意:

- `/member/userlist` に ID を付けないと、別シナリオ「通常配信」(`dYIXAZtz`) に入ることがある
- 画面下部と `#page_message_action` に「下書き保存する」が二重にある。フォーム内だけ押す
- 本文の初期値にプライバシーポリシーと `%unsubscribe%` がある。上書き時は残す
- 実配信・予約は未実装
- 「テスト」に読者が0件だと作成画面が開かない。下書き保存時は自動返信・ステップメールを切ったうえで、ログイン中アドレスを1件だけ登録してから作成する
